# Phase 08 — Integration, evidence and pitch rehearsal

**Prerequisite:** Earlier phases implemented or explicitly scoped as deferred.

**Outcome:** A reproducible local demo and truthful competition evidence package.

## Paste into Codex
```text
Read docs/build-kit/00_MASTER_CODEX_PROMPT.md and docs/build-kit/phases/08_INTEGRATION_RELEASE.md. Inspect the repository and docs/build-status.md. Implement the following phase, preserving approved UI and unrelated work.


Read QA_AND_DEMO.md. Run the integrated app from a clean documented setup, using the frozen corpus version. Verify all routes and the full visitor loop, including poor/unknown scans and unsupported guide questions. Test server ownership, quotas, consent and cleanup. Test real provider access on the available network and record what remains untested.

Capture eight desktop screens and mobile variants, compare to original references, and correct visual drift. Validate contrasts, focus, captions, zoom and reduced-motion behavior. Budget scene loading, avoid cumulative layout shift and confirm guide portrait never covers content. Don't trade the museum identity for generic components during cleanup.

Run focused quality evaluation with actual sample counts and failure cases. Report targets separately from measurements; don't manufacture 20 participants or benchmark photos. Package commands, migrations, corpus manifest, rights record, provider configuration names, failures and a short demo runbook. Scan for secrets/private uploads. Preserve the September submission version; no replacement upload assumed.

Prepare a 60–90 second product walkthrough fitting within a five-minute pitch, a local/recorded backup, and answers for the three-minute Q&A. Make APP_MODE visible in demo evidence. Do not deploy publicly, purchase resources or send submissions without authorization. End with a concise readiness table and exact remaining actions rather than calling everything complete.


Update docs/build-status.md with actual results, blockers and the next phase. Report what is live, fixture-driven, untested or unavailable. Do not claim completion unless the gates below are met.
```

## Acceptance gates

- [ ] Reproducible startup and seed process pass on the available environment.
- [ ] Full visitor loop and source/unknown failure paths work.
- [ ] Visual checklist passes or deviations are explicitly listed.
- [ ] Metrics have sample sizes, versions and actual measured values; no fabricated user results.
- [ ] Five-minute rehearsal fits; backup works without implying unavailable live capabilities.


## Handoff
Release notes, screenshots, benchmark results, demo runbook and backlog. Later expansion: more regions, full accounts, reviewer UI, managed hosting, payments and optional richer avatar animation.
