# Temporary visit state and selected exhibit context

5 October 2026 — Part C UI contracts. These are browser UI behavior, not Phase 03/04/06/07 service completion.

Guide drafts and at most twenty scripted question/answer turns live only in the root React visit provider. They survive internal navigation and language changes during the current document's lifetime. Reloading or closing clears them. Clear conversation removes both draft and history; an outstanding scripted response cannot restore a cleared turn. Questions are bounded to 2,000 characters. No local/session storage, analytics, model call or server save stores this text. History is not used as AI context; all answers remain explicitly scripted. A later real conversation must define owned session storage, consent, context selection, deletion and streaming under Phase 03.

Journey's example stop order, removals, time and interest criteria use the same in-memory lifetime. The selected time/interests are draft criteria. The route's badge uses its last applied time; changing criteria marks the route out of date until Apply regenerates it. Reset example plan restores the original examples and criteria. The tour is explicitly separate from Liaoning and contains the existing Shaanxi, Fujian and Guangdong fixtures. The separate Phase 04 saved-journey panel now uses real owned database routes in both modes; this optional example still stays in memory only. See [the saved-journey contract](personal-journeys.md).

An exhibit's `exhibit` URL parameter carries its identifier from the published drawer into Guide, Journey, Story and interests, and back to the exact source drawer. Each destination retrieves the current published record, refreshes on focus and every fifteen seconds, suppresses results for earlier identifiers/locales/requests, and clears display/actions on withdrawal or failure. Retaining an identifier is not authorization to publish a draft record. Invalid and unavailable records fail closed.

Guide can explicitly seed an editable question about a currently available exhibit in demo mode; reveals/focuses the composer and bounds the draft to 2,000 characters; it never submits automatically. Clear conversation keeps the independently selected exhibit context. Normal navigation without the exhibit parameter leaves that context. Live mode shows the reviewed context and available return link but exposes no scripted composer. Journey offers reading as the available starting action. Story labels its original fiction as a separate example, not an adaptation of the record. Interests do not change automatically from an exhibit; real recommendations remain unconnected.

Region's only province-wide choice is All Liaoning. It sends `region_id=liaoning`, including descendant cities, rather than an unfiltered cross-province query. Map publication indicators distinguish checking, service failure, published-city availability and no published records; geography is separate from publication status. Required atlas attribution is preserved.

The story offers the actual English recording or text only, with its exact English transcript and a labelled Chinese translation. Chinese audio is explicitly unavailable. Guide microphone transcription is also unavailable and disclosed before any action; the disabled control explains typing as the available alternative. No microphone permission is requested.


Part 4 extends the same visit lifetime to catalog query, city, theme and collection/map view. Reload/close clears these; map pan/zoom refits the selected city on reentry. Source browsing keeps its own scope/heading and does not inherit a city filter. Guide state tools are explicitly scripted previews; Stop and Retry use run identifiers so an old/cancelled completion cannot overwrite a newer attempt. Progress/error/refusal are separate from validated answer content; actual approved links are related coverage, not fabricated answer citations. Lens comparison cancellation also invalidates the prior run, with no media/camera permission request. Story player cleanup pauses the native recording on mode/branch exit. External environment checks remain listed in the Part 4 inventory.

## Optional reading and visit bookmarks

`lastRead` holds only the exhibit ID explicitly opened from a publication link or card. Home can reopen that ID through the normal uncached, withdrawal-aware detail loader; Reset continuation clears it. It does not imply the record remains published.

Visit bookmarks are off by default and require explicit opt-in. The root provider holds at most 50 IDs in memory; there is no localStorage, sessionStorage, tracking event or new server write. Turning consent off clears all IDs immediately; individual remove and Clear all are available. Reload/close clears consent, bookmarks and continuation. Saved cards revalidate the current language and publication on mount, focus and every 15 seconds; unavailable/withdrawn results do not retain a stale title or active record link. Durable account/session saves remain later contract work.

Reading size/light surface are temporary dialog preferences. The low-data preference uses the existing preference-cookie pattern (`folkverse_data`, full/low, SameSite=Lax, one year). Its purpose is to skip decorative raster image requests; it is not a tracking or profile cookie. The source-text APIs and authoritative boundaries remain available. Optional numerical contour tiles load only when requested or in low-data map mode; SVG sharpness does not imply finer DEM resolution.

The soundscape is synthesized only after an explicit Play action. No sound autoplays; Stop and leaving the Story close its AudioContext. No recording is made, microphone opened or external audio provider called.
